Scenario 2: Working Set > Cache (Cache Thrashing) BOTTLENECK
  • Working Set: E.g., 2,000 MB exceeds 1,024 MB cache.
  • Disk I/O: High random disk seeks on every query miss.
  • Latency: 10x-50x spike due to NVMe/EBS disk reads.
  • Eviction Penalty: High eviction loops and CPU load.

Technical Explanation: HNSW vs. IVF

              

                HNSW (Hierarchical Navigable Small World): Builds a multi-layer graph of vectors where upper layers enable fast coarse exploration and lower layers provide fine-grained nearest neighbor resolution. MongoDB Atlas Vector Search natively uses HNSW because it offers superior recall (>98%) and low latency without requiring expensive re-clustering phases when new documents are added.


                IVF (Inverted File Index): Partitions the vector space into Voronoi cells using k-means centroids. While fast for very large datasets, IVF requires a separate indexing pass when centroids drift, and is not implemented as a native indexing strategy in standard MongoDB server engines.
